# Decision register — public fragment

This is an excerpt, rewritten for publication. Internal identifiers, host names, customer material, and prompt text are removed. The full register stays private, because the reasoning often names contracts and instructions that are the product’s intellectual property.

Each row is a decision that still binds. “Status” uses the same three words as the rest of this repository. Status is the author’s own assessment and has not been independently verified.

| Id | Decision | Why it was taken | Status |
| --- | --- | --- | --- |
| ZG-01 | Documentation is the only source of truth. Code is the current materialization of an accepted contract. | A specification that is not tied to a graph is either ignored or pasted in whole. Both fail. | Operating |
| ZG-02 | An agent receives a harvest: selected nodes, a chosen depth, and the files it may touch. | The archive is too large to prompt, and too easy to drown in. | Operating |
| ZG-03 | Models translate and converse. Deterministic services compute, validate, assemble context, migrate, and deploy. | Hallucinated arithmetic cannot be audited. A script can. | Operating |
| ZG-04 | The founder hears one voice. Private reasons, steering notes, and flags stay off the screen. | A second voice, or a dump of machine text, breaks trust and leaks the mechanism. | Operating |
| ZG-05 | Save commits the preview already shown. There is no second rewrite at save time. | Otherwise the founder approves a text the system does not store. | Operating |
| ZG-06 | Ambiguous new facts are withheld. Confident facts may still be saved. The founder hears a question, not a flag. | Guessing into the canonical plan is worse than a gap. | Operating |
| ZG-07 | The role that proposes a change does not accept it. | Self-approval was the reliable way to skip a contract. | Operating |
| ZG-08 | A risk reviewer may stop a hop. The implementer may not clear that stop. | Autonomy hides contract drift, weak structure, and a decision that fights an earlier assumption. | Operating |
| ZG-09 | A trivial defect may be fixed in the workshop only when the breach is recorded and the rule is tightened. | Speed is real. An unpriced exception becomes the normal path. | Operating |
| ZG-10 | Parallel work is allowed only on disjoint files, decisions, and gates. The main line moves forward. History is not rewritten. | Side branches were the alternative. The research chose isolation in the loop, and acceptance caught the collisions that remained. | Operating |
| ZG-11 | Secrets must not travel through a prompt or a tool argument, and result files pass a redaction guard. Acceptance uses a dedicated test identity, injected by the runner. | A credential in a prompt is already leaked, including into the next context. | Operating |
| ZG-12 | Closed beta, administration, and acceptance are different allowlists. A public interface description is off on staging and production. | One list is how a test user becomes an operator. | Operating |
| ZG-13 | Scores are instruments. The screen shows one representative number. Bounds stay in an integrator disclosure. | A range on the headline looks like false precision and like a promise. | Operating |
| ZG-14 | External research runs only after the founder confirms the brief. | Unconfirmed search spends money and files facts the founder did not ask for. | Operating |
| ZG-15 | Every defect class leaves a rule, a contract, or a test. Root cause outranks the patch. | The factory’s value is the next decision, not the last hotfix. | Operating |
| ZG-16 | The founder is interrupted for empathy, unusual knowledge, risk appetite, secrets, spend, legal exposure, irreversible data, and emergency stop. | Asking the founder to certify code they cannot assess is theater. Not asking them about taste is how products become the model average. | Operating |
| ZG-17 | The platform graph and a founder’s customer product are separate worlds: data, secrets, and runtime. | Sharing a machine must not share a database. | Specified |
| ZG-18 | Materialization is a versioned compiler. Agents author the graph. They do not edit the promoted tree as the source of truth. | Otherwise the running code drifts from the decision that justified it. | Specified |
| ZG-19 | Agents may raise a risk class. They may not lower a deterministic trigger. Production is an input to risk, not an automatic founder click. | A model that can talk itself into “low risk” is not a control. | Specified |
| ZG-20 | When delivery is beyond what the current run can do, the ladder is: another independent review, a specialist agent, a founder decision the founder can actually make, a guided external service, then a technical handoff with the graph, the contracts, and the open decisions attached. | The product may attempt ambitious work. It may not pretend the model already finished it. | Specified |
| ZG-21 | A product keeps a stable identity, versioned requirements, and recoverable prior versions while it keeps changing. Several product lines may diverge on purpose from a shared core. | “Product as a process” is not uncontrolled mutation. | Horizon |
| ZG-22 | The best product for one segment, one week, and one cost curve is not the best product for the next. Zenonum’s job is to make that change observable and reversible. | A single static compromise is the black Model T. Cheaper software removes the excuse. | Horizon |

ZG-01 through ZG-16 are the rules the closed beta was actually built under. ZG-17 through ZG-20 are decided architecture for the delivery stage. ZG-21 and ZG-22 are the product thesis those decisions serve.

Nothing in this fragment is a prompt, a formula, or a customer fact.
