# Interface

The interface is a control room for a non-technical founder, plus a separate administration door. It is operating in the closed beta.

The visual system is editorial on purpose: warm paper, ink, and copper. Copper means an action. Blue means structure. Strategy, product, and execution are three stable layers so a large map does not become one color of “AI.” The screen explains learning. It does not explain plumbing.

## What the founder sees

| Surface | What it is for | Trust rule |
| --- | --- | --- |
| Discovery, before an account | A short conversation that can continue after sign-in | A guest cap is honest. The session is kept |
| Strategy map | Nodes, layers, and regions, including a Lean layout | Off-map items (project, founder, tasks, risks, contradictions) stay in queues so the drawing stays readable |
| Coach | One conversation on the open node | Only the coach’s message is shown. Machine notes stay hidden |
| Extraction preview | The exact text Save will commit, grouped by node | If it is not in the preview, it is not committed |
| Inspector | Statement and variables for the selected node | One representative number. Bounds only behind an integrator disclosure |
| Search | Find a node by its words, then broaden to related ideas | Results name the node type. No jargon about indexes |
| Timeline | The same plan as time: scheduled, unscheduled, done | Read-only. It shares the selected node with the map |
| Required moves and next moves | Why the system is asking, and what is worth doing next | Heuristics, labeled as heuristics |
| Research | Reports from a confirmed external brief | The brief is confirmed before the search runs |
| Budget | What the workspace may still spend | A spent budget is a clear stop, not a chat error |
| Working state | A quiet chip when a save or unlock is still updating the map | The map does not jump. The founder can keep working |

Mobile is a first-class layout: sheets and peeks, not a desktop squeezed down.

Sign-in for the closed beta is an allowlisted identity. There is no public registration form pretending otherwise.

## What the administration door sees

Administration is not a mode of the founder session.

It is where prompts and skills are tuned, models are chosen per background agent, feedback is read, and test operations are run. The founder-facing coach cannot open it. The people who tune agents are not the same turn as the person being coached.

Observability records inputs and outputs of agents and services with correlation, timing, and redaction. That record is for operators. It is not a second chat.

## Interaction rules that are governance

These are product rules, not polish.

- Save commits the preview the founder already read.
- Close can return the founder to the map while heavier updates finish in the background.
- A required-move conversation does not hijack a coach that is already open. It waits.
- The coach explains why a required move opened, before it proposes.
- Links in a coach message are either safe external addresses or a node the founder can open.
- Search focuses its field when opened, so typing works immediately.
- The inspector can be resized on a desktop and stays a sheet on a phone.

## Specified next surfaces

The delivery stage adds an assurance center the founder can read in the same language as the map: what is known to work, what has not been tested, and which product line or experiment is exposed. Test runs, screenshots, and traces stay operational records. They link to a scenario and a release. They do not become one node per click.

The founder still enters through conversation and the map. Advanced controls exist for someone who wants them. The default path does not require knowing which executor ran the work.
